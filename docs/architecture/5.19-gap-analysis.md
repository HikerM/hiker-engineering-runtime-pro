## 关键架构风险

- `RISK-001`：直接把现有JSON writer旁接SQLite会形成两个权威事实源；必须通过迁移协议和单一Coordinator避免双写长期化。
- `RISK-002`：把所有Artifact放入SQLite会造成WAL膨胀和热路径退化；大型对象必须内容寻址外置。
- `RISK-003`：把Agent推理包在事务内会制造写锁饥饿；Snapshot与CAS必须物理分离。
- `RISK-004`：把“Runtime Contract”实现成Codex事件结构别名会锁死Provider；核心模型只保留中性状态与Artifact/Event协议。
- `RISK-005`：License检查进入每次状态读写会污染Hot Path；授权应在能力边界验证并缓存签名结论。
- `RISK-006`：把Synthetic/Accelerated结果标为Field Proof会造成商业误导；证据等级必须成为机器字段。

## 推荐决策

- `DEC-001`：使用.NET 9编译Runtime；当前环境具备SDK，Native/单文件发行可在发布阶段验证。
- `DEC-002`：StateStore Contract与SQLite/WAL为第一实现，业务层不得直接依赖SQL。
- `DEC-003`：Pro作为独立私有仓库和独立包，不复制Community源码；通过明确Community Adapter和版本指纹集成。
- `DEC-004`：采用Current State +语义Event Journal，不做纯Event Sourcing。
- `DEC-005`：商用签名采用标准非对称密码；测试只使用临时生成密钥，真实私钥永不进入仓库。
