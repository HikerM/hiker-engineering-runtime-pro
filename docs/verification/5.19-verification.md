# 5.19 Verification

本文定义 Hiker 5.19 Pro 的可重复验证入口和证据边界。验证工具只在显式调用时运行，不进入 Runtime 热路径，也不写入产品 `.ai`。

## 证据等级

- `DETERMINISTIC_VERIFIED`：确定性状态、Schema、签名、策略或 Gate 由程序复现。
- `SIMULATION_PROVEN`：真实生产实现承受合成规模、并发或故障；不代表真实客户项目。
- `REAL_INTEGRATION_PROVEN`：与真实 SQLite、Git、Filesystem、Process、HTTP、PostgreSQL、GitHub 或 Codex CLI 集成。
- `FIELD_PROVEN`：需要真实客户和日历时间数据；首个 RC 允许明确标记 `NOT_YET_PROVEN`。

## 故障注入

自动测试覆盖：

- Lease reserve 后 Runtime 启动失败；
- Event insert 失败时 Domain 和 operation journal 同事务回滚；
- Goal Change 后旧 generation 的 CAS 被拒绝；
- Artifact 流中断后临时文件与元数据均不残留；
- Checkpoint 后使用验证过的事实恢复；
- Handoff ownership transfer 后目标恢复失败，进入 `RECOVERY_REQUIRED` 且不重放 transfer；
- Runtime drain 后 Shutdown 失败，保持 `DRAINING` 且不重复 Release；
- Release Candidate event 失败不产生半 Candidate；
- 损坏 Migration/Restore 源在改写当前状态前被拒绝。
