# Hiker 5.19 Pro Release Process

发布工具只按需运行，不进入 Hiker Runtime 热路径。发行私钥由发布方在仓库外管理；源码、测试 Fixture、GitHub 仓库和 ZIP 都不得包含私钥。

## 1. 版本与源码门禁

```powershell
dotnet run --project tools/Hiker.Pro.Release -c Release -- version-check --root .
dotnet format Hiker.Pro.slnx --verify-no-changes --no-restore
dotnet test Hiker.Pro.slnx -c Release --logger "trx;LogFileName=unit-tests.trx" --results-directory artifacts/verification
```

版本唯一来源是 `eng/Version.props`。`VERSION` 与 `release-versions.json` 是兼容性镜像，任何漂移都会阻断构建。

## 2. 外部签名密钥

使用组织批准的 ECDSA P-256 密钥设施。验证或候选演练可以在仓库外生成一次性密钥，但必须将其分类为 RC 证据密钥，而不是生产长期信任根。

```powershell
openssl ecparam -name prime256v1 -genkey -noout -out <external-private-key.pem>
```

禁止把 `<external-private-key.pem>` 放入仓库、`artifacts/`、Fixture、日志或发布目录。构建工具会拒绝仓库内及发布输出内的私钥路径。

一次性 RC 验证也可通过标准输入传递 PEM，避免私钥落盘：

```powershell
openssl ecparam -name prime256v1 -genkey -noout | dotnet run --project tools/Hiker.Pro.Release -c Release -- build `
  --root . --output artifacts/release --private-key-stdin --key-id <rc-key-id> --runtime win-x64 --channel rc
```

## 3. 构建签名 RC

构建只接受干净的 `main`：

```powershell
dotnet run --project tools/Hiker.Pro.Release -c Release -- build `
  --root . `
  --output artifacts/release `
  --private-key <external-private-key.pem> `
  --key-id <approved-key-id> `
  --runtime win-x64 `
  --channel rc
```

输出包括 ZIP、外部 SHA-256、公开验证密钥和无秘密的 release facts。ZIP 内 `manifest.json` 使用 ECDSA P-256 签名并覆盖每个 Payload 文件的相对路径、大小和 SHA-256，同时绑定产品版本和 Git commit。

## 4. 独立验证与 Clean Install

发布验证必须从受信任渠道取得公钥 Fingerprint，不能只信任与 ZIP 同时下载的公钥文件：

```powershell
dotnet run --project tools/Hiker.Pro.Release -c Release -- verify `
  --package artifacts/release/<candidate>.zip `
  --public-key artifacts/release/<candidate>.public.pem `
  --public-key-sha256 <out-of-band-fingerprint> `
  --key-id <approved-key-id> `
  --report artifacts/verification/release-package.json
```

验证器执行：外部 Checksum、Pinned Trust Root、Manifest Signature、逐文件 Hash、未列出文件拒绝、源码/Debug Symbol/秘密/本机路径扫描、隔离 `version/init/doctor/status/backup/export`，以及单字节篡改拒绝。

## 5. 最终商业 Gate

完整 Gate 要求所有报告来自同一干净提交，并要求 Private GitHub `origin/main` 与本地 HEAD 一致：

```powershell
dotnet run --project tools/Hiker.Pro.Release -c Release -- gate `
  --root . `
  --public-root <community-5.18-root> `
  --evidence artifacts/verification `
  --release-root artifacts/release `
  --test-results artifacts/verification/unit-tests.trx `
  --output artifacts/verification/commercial-release-gate.json
```

只有输出 `PASS_5_19_COMMERCIAL` 且不存在 P0，才允许把该 ZIP 作为 5.19 商业候选。真实日历一年、真实客户生产运行和多 Provider 现场数据继续明确标记 `NOT_YET_FIELD_PROVEN`。
